StrideForge

Quadruped design and a first imitation-training run

15 October 2026 · Updated 16 October 2026

Ongoing project. This is an ongoing hobby project. The design files and code aren’t public yet. If there’s enough interest, I’ll consider releasing them.

I’m working on StrideForge to learn more about legged robots and simulation. The work now covers the leg mechanism, a four-legged CAD assembly, learned walking in MuJoCo and a first training run using a dog-motion reference. The physical robot is still to be built.

I’m keeping a public build journal with the design revisions, images and simulation results.

Leg mechanism

Each leg has three AK45-36 actuators: hip roll, hip pitch and knee. That gives the quadruped 12 actuated joints. The latest revision has separate left and right leg assemblies, with both knees folding rearward.

The thigh and shin each have 160 mm between joint centres. Short 3D-printed end fittings connect to purchased 20 × 20 × 80 mm aluminium profiles using standard fasteners. I’m using vendor-derived motor housings and output parts in FreeCAD to study the mechanism and how the parts fit together.

From CAD to simulation

The standing model has URDF and MuJoCo versions with a floating base. Its estimated mass is 8.731 kg. The simulation uses idealised actuators within the documented limits; the motor behaviour will need checking against measurements from a physical unit.

The earlier B2 standing test ran for six seconds with all four feet in contact with the ground. Peak joint torque was 4.596 N·m under an 8 N·m simulation cap, and the maximum body tilt was 1.87°.

That gave me an initial check of the assembled model, contacts and standing control. I then moved on to the B3 walking model and PPO training.

16 October: first dog-motion imitation run

The first imitation-training run is complete. I used the B3 MuJoCo model and a retargeted dog-trot reference, with PPO learning small joint-target corrections around the reference controller. This follows the earlier reward-only walking policy.

The run collected 1,001,472 transitions in about 18 minutes on CPU. The logged mean episode return rose from −4.49 to 56.90, and the final mean episode length reached the full 20-second limit. Those are training statistics; they don’t by themselves show how closely the robot follows the dog motion.

A separate 20-second check with the recorded training controller settings reached 3.39 m, averaging 0.170 m/s without falling. It is still below the reference’s 0.223 m/s, and foot lift is uneven, particularly at the rear. Repeating the same fixed-start check gave the same trajectory, so this doesn’t establish robustness to different starts or disturbances.

The motion reference comes from motion_imitation / AI4Animation, with source motion data licensed under CC BY-NC 4.0.

What comes next

I’ll use this first result to improve foot clearance and reference tracking, then check more varied starting states. The physical robot is still to be built. Before buying a full set of actuators, I plan to test one motor and use the measurements for system identification.

The build journal has the run settings, measured results and earlier design revisions.
